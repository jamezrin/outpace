# Outpace 1.0.1

For publication status and downloads, see the
[GitHub Release](https://github.com/jamezrin/outpace-stream/releases/tag/v1.0.1).
These notes accompany the reviewed release commit; source documentation can precede publication.

Outpace 1.0.1 is a patch release. It fixes live audio normalization (`OUTPACE_LIVE_AUDIO_NORMALIZE`
and `OUTPACE_HLS_AUDIO_NORMALIZE`), which could end live streams or refuse common AC3 sources.
It adds no features and changes no defaults. Users who leave normalization off are only affected
by the AC3 track handling described below.

## Fixes

- **Normalization no longer ends live streams on ordinary source behavior**
  ([#447](https://github.com/jamezrin/outpace-stream/issues/447),
  [#449](https://github.com/jamezrin/outpace-stream/pull/449)):
  - Each new conversion generation looked for fresh PAT/PMT tables and the next video access point
    within 1 MiB, so a generation starting mid-GOP on a high-bitrate source failed with
    `input_overflow`. Classification now has its own 16 MiB evidence bound, and scanned bytes
    are discarded rather than retained.
  - A single source chunk larger than the 1 MiB input budget failed with `input_overflow`.
    Views above 512 KiB are now read in place.
  - Upstream reconnects every 15 to 30 seconds used up the limit of three recoveries per minute
    and ended the session with `recovery_limit`. A restart no longer counts toward the limit when
    the output before it had been playing for at least 10 seconds.
  - Normalization failures and recoveries are now logged under `[audio]` with their reason code.
- **AC3 signalled as ATSC stream type `0x81` is now converted**
  ([#448](https://github.com/jamezrin/outpace-stream/issues/448),
  [#451](https://github.com/jamezrin/outpace-stream/pull/451)). FFmpeg's MPEG-TS muxer writes AC3
  this way by default. Previously only DVB signalling (stream type `0x06` with an AC-3 descriptor
  or registration) was recognised, and such sources were refused with `422` and
  `normalization.failure = "unsupported"`. ATSC E-AC3 (`0x87`) is now recognised too: it is
  skipped when a convertible track is present and refused when it is the only audio. A codec
  descriptor contradicting the stream type still refuses the stream.

## Behavior change with normalization off

The default native HLS output already keeps only the first AAC track when a stream has one, and
drops DVB-signalled AC3 and E-AC3 tracks. ATSC `0x81` and `0x87` tracks are now dropped in the same
way. Streams without an AAC track, and direct MPEG-TS output, are unchanged.

## Distribution

Targets, packages, images, provenance and service integrations are unchanged from
[1.0.0](https://github.com/jamezrin/outpace-stream/blob/main/docs/releases/1.0.0.md#distribution). A build-dependency update (`cc` 1.11.2) is included.

## Upgrade and rollback

Upgrading from 1.0.0 needs no configuration change. Pin the `1.0.1` image or binary, restart,
then check `/healthz` and playback. Keep the 1.0.0 binary or image for rollback.

## Validation and limits

The fixes are covered by unit tests, a synthetic PAT/PMT vector and the opted-in FFmpeg
acceptance suite, including FFmpeg's default AC3 mux on both the HLS and shared live TS routes.
The `0x81` conversion path has not yet been exercised live against a real AC3 source. No new
multi-hour soak, live comparison or hardware qualification was performed for this release.
Preparation checks and candidate CI are recorded in the release preparation PR.
