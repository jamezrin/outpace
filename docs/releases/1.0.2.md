# Outpace 1.0.2

For publication status and downloads, see the
[GitHub Release](https://github.com/outpace-stream/outpace-engine/releases/tag/v1.0.2).
These notes accompany the reviewed release commit; source documentation can precede publication.

Outpace 1.0.2 is a patch release and the first one published from the
[outpace-stream](https://github.com/outpace-stream) organization. It fixes the warm peer cache on
Android and other hosts whose data directory sits under an execute-only parent, and bounds the
opt-in `/metrics` endpoint. It also adds a best-effort 32-bit Android archive. It changes no
defaults and needs no configuration change.

## Fixes

- **The warm peer cache now opens under execute-only parent directories**
  ([#456](https://github.com/outpace-stream/outpace-engine/issues/456),
  [#464](https://github.com/outpace-stream/outpace-engine/pull/464)). On Android, apps can traverse
  but not list directories such as `/data`, so the cache was never reached. Every start was cold
  and the log showed `[ace] warm peer cache I/O failed; streaming continues without durable hints`.
  Termux and any Linux deployment with an execute-only ancestor were affected the same way. On
  Linux and Android the cache path is now traversed with `O_PATH`. Ownership and mode checks,
  symlink rejection and the exclusive writer lock are unchanged. Other Unix platforms keep their
  previous behavior.
- **`GET /metrics` scrapes are bounded**
  ([#466](https://github.com/outpace-stream/outpace-engine/issues/466),
  [#468](https://github.com/outpace-stream/outpace-engine/pull/468)). With `OUTPACE_METRICS=1`, at
  most two scrapes collect a snapshot at the same time, and each has two seconds. A scrape over
  either limit gets `503 Service Unavailable` with `Retry-After: 1` and an empty body, which
  Prometheus records as a failed scrape rather than partial values. A normal scrape interval from
  one or two Prometheus servers never reaches these limits. Nothing changes with metrics off.

## Distribution

- **Organization paths.** The repository is now
  [outpace-stream/outpace-engine](https://github.com/outpace-stream/outpace-engine), and images are
  published to `ghcr.io/outpace-stream/outpace-engine` (`1.0.2`, `1.0.2-minimal`, `latest`,
  `minimal`). Images up to 1.0.1 at `ghcr.io/jamezrin/outpace` stay available for rollback but
  receive no new tags. The Homebrew tap and Scoop bucket moved to
  `outpace-stream/homebrew-outpace` and `outpace-stream/scoop-outpace`. Archive and package names
  are unchanged.
- **Provenance.** 1.0.2 archives, packages and images are attested by
  `outpace-stream/outpace-engine`. Verify a downloaded file with
  `gh attestation verify <file> --repo outpace-stream/outpace-engine`, and an image with
  `gh attestation verify oci://ghcr.io/outpace-stream/outpace-engine:1.0.2 --repo outpace-stream/outpace-engine`.
  Releases up to 1.0.1 keep
  their original signer identity; see
  [Installation](https://github.com/outpace-stream/outpace-engine/wiki/Installation#verify-where-a-release-came-from).
- **32-bit Android.** A best-effort `armv7-linux-androideabi` archive is published next to
  `aarch64-linux-android`
  ([#459](https://github.com/outpace-stream/outpace-engine/issues/459),
  [#462](https://github.com/outpace-stream/outpace-engine/pull/462)), for Android TV boxes that run
  a 32-bit userland. Like the 64-bit Android archive, it is optional: a failed Android build never
  blocks the release.
- **Arch Linux.** The community AUR packages `outpace-bin` and `outpace-git` are now documented on
  the [Installation](https://github.com/outpace-stream/outpace-engine/wiki/Installation#arch-linux-aur)
  page.

Targets, packages and service integrations are otherwise unchanged from
[1.0.0](https://github.com/outpace-stream/outpace-engine/blob/main/docs/releases/1.0.0.md#distribution).

## Upgrade and rollback

Upgrading from 1.0.1 needs no configuration change. If you pull images, switch the image name to
`ghcr.io/outpace-stream/outpace-engine:1.0.2`. If you installed with Homebrew or Scoop before the
move, re-add the tap or bucket from its new repository. Restart, then check `/healthz` and
playback. Keep the 1.0.1 binary or image for rollback.

## Validation and limits

The cache fix is covered by a regression test that writes, reopens and reads a cache beneath an
execute-only parent, which failed with `EACCES` before the fix. CI now checks that this test runs as
a normal user instead of skipping
([#469](https://github.com/outpace-stream/outpace-engine/pull/469)), and cache test fixtures wait for
the real load instead of a 100 ms best-effort window. The metrics bounds are covered by unit tests
for refusal, timeout and the 503 response. No new multi-hour soak, live comparison or hardware
qualification was performed for this release. Preparation checks and candidate CI are recorded in
the release PR.
