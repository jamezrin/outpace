# Outpace 1.0.0

For publication status and downloads, see the
[GitHub Release](https://github.com/outpace-stream/outpace-engine/releases/tag/v1.0.0).
These notes accompany the reviewed release commit; source documentation can precede publication.

Outpace 1.0.0 brings the features merged since 0.9.0 to release binaries and multi-architecture
images. It supports public, unencrypted live and single-file VOD playback, reciprocal seeding,
signed MPEG-TS broadcasting and the documented AceStream-compatible HTTP subset. Premium
content, accounts and a bundled player/UI remain permanent non-goals.

## Features

- In-memory live HLS timeshift (`OUTPACE_HISTORY_*`), with per-viewer rewind and bounded
  per-source and shared memory budgets. It is not persistent recording.
- HLS-origin descriptors and opt-in managed relay (`OUTPACE_MANAGED_HLS`), including gzip
  playlists, connection reuse, `X-Outpace-Upstream-Status` and qualifying origin replay.
- Shared live audio normalization (`OUTPACE_LIVE_AUDIO_NORMALIZE`) before TS/HLS/support
  fan-out. FFmpeg is required when enabled; it is not bundled in published images.
- Outbound-only private peer mode, local descriptor aliases and `/network-policy`
  (`OUTPACE_PRIVATE_PEERS`, `OUTPACE_PRIVATE_DESCRIPTORS`).
- Support sources kept active without viewers (`OUTPACE_SUPPORT_SOURCES`) and `/support`.
- Optional encrypted SRT ingest in native Linux builds with `--features srt` and an
  encryption-enabled libsrt 1.5.7 or newer. Standard release archives and images omit SRT.
- Separate, default-off service-backed `/search` (`OUTPACE_COMPAT_ACESTREAM_SERVICES`).
  It uses external plain-HTTP services and bounded signed-response adaptation; search data
  is not proof of a verified playback descriptor. Reverse infohash-to-content-ID lookup is
  unsupported. Client endpoint/parser integration and deployed scraper qualification are
  not established by the local adapter tests.
- Opt-in Prometheus `/metrics` (`OUTPACE_METRICS=1`), disabled by default.

## Fixes

- Ended HLS sources close playlists with `#EXT-X-ENDLIST` rather than returning `503` forever.
- Live `get_media_files` reports MPEG-TS MIME and a display filename.
- The prebuffer deadline is absolute from the first media byte; source gaps cannot restart it.
- Shutdown ends viewer responses before draining HTTP; idle cleanup remains responsive when
  another stream's cleanup is stuck.
- CLI compatibility parsing rejects duplicate query keys and unsupported file selections;
  HTTP compatibility still accepts the Android SDK's duplicated descriptor parameters.

## Distribution

- Ten required binary targets: Linux musl x86_64, ARM64, ARMv7, ARMv6 hard-float and RISC-V 64;
  macOS Intel and Apple silicon; Windows x86_64 and ARM64; FreeBSD x86_64.
- Debian/Ubuntu `.deb` and Fedora-family `.rpm` packages for x86_64, ARM64 and ARMv7, with a
  systemd service and configuration file. Installation does not start the service.
- Debian-based and minimal `scratch` images for linux/amd64, linux/arm64 and linux/arm/v7.
  Minimal images use `outpace healthcheck` and have no shell, curl or package manager.
- Signed build provenance for standard archives, packages and release images. Verify with
  `gh attestation verify`; use `SHA256SUMS` for archive/package integrity.
- Windows service management, a macOS LaunchAgent, a FreeBSD rc.d script and an OpenWrt
  installer/procd service. Consult the wiki before installing on a router or firewall.
- Best-effort Android ARM64 archive for Termux, uploaded separately after core publication.
  It may be absent if its build fails and uses its own `.sha256`, not `SHA256SUMS`.
- Homebrew/Scoop definitions use the published release checksums. The active `.env.example`
  image pin targets 1.0.0.
- Standard release binaries use the size-optimized `dist` profile; source `--release` and
  edge builds keep their existing profile. See the merged profile work in
  [#429](https://github.com/outpace-stream/outpace-engine/pull/429) for its measurements.

## Upgrade and rollback

Back up the data directory (including node identity and broadcast keys), pin the release tag,
recreate the container or restart the service, then check `/healthz` and playback. Keep the old
binary/image and configuration for rollback. Stop active broadcasts deliberately before an
upgrade. The release preparation itself changes no listener, seeding, caching or opt-in defaults.

Timeshift, managed relay, private peers, support sources, shared normalization, external search
and metrics retain their documented opt-in settings. Private peers restrict discovery and inbound
behavior; search is rejected in that mode. Review the
[wiki configuration reference](https://github.com/outpace-stream/outpace-engine/wiki/Configuration)
before enabling them. `/healthz` is liveness, not proof of media delivery.

## Deferred scope

The maintainer explicitly deferred the following for 1.0.0 on 2026-11-13:

- [#79](https://github.com/outpace-stream/outpace-engine/issues/79): multi-file/selected-file VOD.
  Multi-file descriptors remain rejected; verified layout/schema evidence is required before
  implementing offsets and selection. Single-file playback remains supported.
- [#269](https://github.com/outpace-stream/outpace-engine/issues/269): optional broadcast discovery
  and metadata wire fields. Recovered key/accessor/conversion evidence does not prove the full
  producer-to-consumer chain, endpoint policy, persistence or advertisement semantics. No new
  metatracker/startup-node or tags/logo/description options are adopted.
- [#272](https://github.com/outpace-stream/outpace-engine/issues/272): original-engine HLS transport
  origination/support parity. Native TS-to-HLS packaging and managed upstream relay are supported
  subsets, not proof of original-engine HLS peer/discovery/origination interoperability. New
  origination requires protocol evidence, URL/DNS/redirect policy, sequence/discontinuity rules,
  cancellation/cache bounds and synthetic topology tests before implementation.

[#128](https://github.com/outpace-stream/outpace-engine/issues/128) remains a conditional enhancement:
VOD HLS uses approximate byte-based segmentation without PCR/keyframe-aligned media-time seeking.
Schedule that work after a demonstrated player/interoperability failure. This release does not
promise a DHT keyword crawler or aggregate playlist; known-hash DHT peer discovery is supported.

## Validation and limits

The [#195 acceptance reconciliation](https://github.com/outpace-stream/outpace-engine/issues/195)
records a reviewed 7,500-second matched observation with more than 7,200 sampled active seconds
per player, plus separate recovery, integrity and resource-admission evidence. The maintainer
recorded [production-replacement sign-off on 2026-11-12](https://github.com/outpace-stream/outpace-engine/issues/210#issuecomment-6827431678).
This was human acceptance, not a new passing soak of the final 1.0.0 candidate.

The historical stale-reconnect stall [#246](https://github.com/outpace-stream/outpace-engine/issues/246#issuecomment-6827432729)
was closed as not reproduced/inconclusive, not as causally fixed. Retain failed observations;
reopen with timestamped private diagnostics if it recurs. Reference-relative latency to live
remains unmeasured. Sampled decode progress does not prove sub-poll smoothness, identical bytes,
24/7 availability or leak-free behavior. Session admission is configurable and unlimited by
default; there is no new aggregate seed-store byte budget.

Preparation checks and final candidate CI results are recorded in
[release PR #444](https://github.com/outpace-stream/outpace-engine/pull/444). The
[release workflow](https://github.com/outpace-stream/outpace-engine/actions/runs/43405107975) completed
successfully on 2026-11-13. All ten required archives and six packages matched `SHA256SUMS`,
and their attestations verified against the source tag and commit. The optional Android archive
also matched its separate checksum.

Both standard and minimal image indexes contain linux/amd64, linux/arm64 and linux/arm/v7;
`latest` and `minimal` match their respective versioned digests. Image provenance, source/version
labels, local x86_64 version output and daemon health checks passed. The downloaded Linux x86_64
binary reports `outpace 1.0.0`. These publication checks are not a new live comparison, multi-hour
soak or hardware qualification. They do not establish behavior on every listed operating system
or on 16 KiB-page ARM hardware. Android remains best-effort for future releases.
