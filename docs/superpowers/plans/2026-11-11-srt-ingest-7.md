# Optional SRT ingest implementation plan

> Use superpowers:executing-plans inline. Routine design/plan approval checkpoints
> are waived by the user goal. One fresh whole-feature review at the end.

**Goal:** Complete milestone #7 encrypted SRT MPEG-TS ingest through existing signed
broadcast ownership, with conservative defaults and bounded native/async work.
**Architecture:** Optional system reference libsrt feature, private C ABI shim,
thread-confined socket/poll owner and bounded Tokio ingest handoff. Existing
ProducerSession/BroadcastIngest owns signing and durable cursor continuity.
**Tech Stack:** Rust pinned toolchain, Tokio, C compiler, libsrt >=1.5.7.
**Spec:** docs/superpowers/specs/2026-11-11-srt-ingest-7-design.md

## Global constraints

No default listener or native dependency; explicit numeric bind and encrypted PSK
file only. One native owner thread, <=10ms waits, finite batches, four <=64KiB
messages plus one pending per admitted socket. Config cap1..16/default4, latency
20..2000/default120ms, explicit1MiB native send/receive buffers and effective option
readback. No application logging framework, secret-bearing URL/log, new protocol,
HTTP/RTMP behavior change, public validation or firewall/routing/config mutation.

## Review focus

- A rejected/wrong-key publisher must not create broadcast state or retain a slot.
- Full media queues must not starve native control/cancellation/other publishers.
- Last join waiter cancellation must not detach a thread or release producer early.
- Oversized SRT messages/TS fragmentation must not publish truncated media.
- Disconnect during durable piece publication must not reset identity/cursor.

## Task 2: Owned listener, bounded handoff and broadcast producers

Files: src/srt.rs, src/srt/owner.rs, src/srt/ingest.rs; broadcast.rs ProducerKind;
runtime.rs lifecycle integration. Reuse existing CleanupTracker/ProducerSession.

- [ ] Write actual full-channel/control/cancel/overflow and two-publisher fairness
  REDs around real native owner, not mocked successful shutdown.
- [ ] Open native listener only inside its owned thread. Async workers receive
  typed bounded open/media/close events and unique connection tokens. At most one
  pending chunk per connection; pause native read interest on full handoff. Bounded
  control storage plus separate latched shutdown cannot depend on media capacity.
- [ ] Validate bounded nonsecret StreamID before acquiring broadcast producer. Hold
  claims while native retirement and in-flight ingest operations remain unresolved.
  Add explicit Srt producer kind to existing exclusive acquisition, not a parallel
  broadcast map or identity store.
- [ ] Feed TS across message boundaries via existing ingest framing/chunker; reject
  unexpected message limits/profile. Report actual byte/commit counters separately
  from received/dropped/disconnect observations.
- [ ] Implement explicit retirement acknowledgments and confirmed thread join on
  cleanup-owned blocking context; no close/join on critical Tokio event loop.
  Initialize/cleanup global native library under counted ownership only after all
  sockets/polls are gone. Drop transfers cancellation, never claims confirmed exit.
- [ ] Prove stale generations, shutdown-before-ready, queue full, cleanup uncertainty,
  source conflict, slot reuse and async-waiter cancellation with deterministic controls.
