# Native HTTP MPEG-TS Broadcast Pull Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. The user selected a fresh implementer and fresh reviewer for each task; root handles orchestration.

**Goal:** Implement #206: attach one private-status HTTP(S) MPEG-TS source to a broadcast, with guarded reconnects, exclusive ingress, restart-safe piece reservations and owned cleanup under the approved platform guarantees.

**Architecture:** Share a guarded streaming HTTP client in `ace-swarm`, then make existing broadcast ingress fallible, exclusive and reservation-backed. An entry-owned controller owns ingress, persistence and announcement lifetimes; a pull worker reuses the existing TS/sign/store path and native routes. Environment declarations reattach at service startup, while API attachments remain process-local and identity persists independently.

**Tech Stack:** Pinned Rust toolchain, Tokio watch/mutex/tasks, axum, serde/serde_json, reqwest 0.13.5/Hyper 1.11.1 with rustls/ring and bundled roots, existing `libc`, existing signing/chunking/store/seed APIs. No new supervisor, database or cancellation package.

**Spec:** [Approved #206 design](../specs/2026-10-23-broadcast-pull-design.md). Read the entire spec before implementation; its API tables and finite validation matrix are normative. The private `/tmp/outpace-206/platform-resolution.md` supplies historical evidence only: the user's subsequent approval, recorded in the spec, resolves its pending-decision wording.

## Global Constraints

- “Accept only the public, unencrypted origination scope already supported by the repository.” Scope is #206 only; no UI, HLS-source parser, transcoder, Range resume, durable API job, auth framework, framework replacement or wire/seed redesign.
- “Retain existing seeding limits, cache settings, bind defaults and tracker behavior.” Preserve `RtmpTsMuxer`, TS resync, descriptor geometry, raw PUT's immediate `200` and binary descriptor GET. Geometry remains 65,536/16,384; ordinary finite PUT/RTMP finish once, including existing short-tail limitations.
- “Do not call `finish()` for pull EOF, retry, detach, shutdown or errors.” Reconnect creates fresh resync/signing state under the same exclusive pull claim; consume every exposed piece index permanently.
- “Use existing Tokio watch cancellation and owned handles; do not introduce a cancellation dependency or general task supervisor.” No global map lock across network/filesystem/joins; preserve a stopping placeholder and owned blocking-I/O fence on timeout.
- Reservation block is 128 pieces, `reserved_until` is exclusive, and admission/reservation success precedes publication. Fail closed on uncertain persistence and existing invalid/unreadable records; explicit diskless operation never substitutes for disk failure.
- Windows: “process-crash/ordinary daemon restart guarantee while the OS/filesystem state remains intact”, with no system-crash/power-loss guarantee. Preserve supported PUT/RTMP/CLI and add pull without requiring Windows directory sync or elevated execution. Linux checks namespace/link sync; macOS separates file full-sync from directory `fsync`. Document filesystem/storage assumptions and rollback risks; do not claim platform equivalence.
- RTMP acceptance is “broadcast-operation quiescence and fencing”, plus stopping/joining the owned listener at runtime cleanup. Established dependency-owned connection tasks may survive; every later callback must respect admission closure/session generation. Do not vendor or redesign `rtmp-rs`.
- Source defaults/ranges: connect 5 seconds (1..=60), read 15 seconds (1..=300), reconnect initial 1 second and maximum 30 seconds (each 1..=300, initial <= maximum). DNS 5 seconds, headers 15 seconds, aligned-progress 30 seconds, local ingest 15 seconds, healthy reset 30 seconds, shared cleanup grace 5 seconds.
- Map input <=256 KiB UTF-8 and <=64 entries; URL <=8,192 bytes; source request <=16 KiB. Names: 1–64 ASCII letters/digits/`.`/`_`/`-`, excluding `.` and `..`. Reject duplicate/unknown fields. Only exact `1` enables `OUTPACE_ALLOW_NON_GLOBAL_BROADCAST_SOURCE`, independent of transport/tracker switches.
- Source fetch: fresh client/attempt, selected-address pinning, no proxies, redirects, hidden retries, compression, Range/conditional requests or unsafe TLS settings. HTTP/1 only, <=64 headers, <=32 KiB parsed header bytes; retain the locked parser's 417,792-byte bound. Feed slices <=64 KiB; reject frames >256 KiB. No source lifetime/body-byte ceiling; buffer claims cover application-retained state only.
- Source URLs, query tokens, hosts/addresses, underlying errors and keys never enter status/logs/Debug. Use the spec's exact envelopes, status/error vocabulary and `alog!` fixed-code events, at most once per source per 30 seconds plus one terminal event. No generated identity fields in new logs.
- No real content IDs, infohashes or upstream media names in any tracked artifact or review/commit prose; never read the identifiers registry. Use synthetic packets/names/URLs and in-memory generated identities only. No public network, catalog, tracker, DHT, FFmpeg/live ignored tests, probes or installations.
- All test authoring/migration, test execution, builds, fmt, clippy, hygiene and hook-running commits belong to **GPT-6 Luna**. All production implementation and reviews belong to **GPT-6.1 Sol**. Reviewers request checks from Luna; they do not run them themselves.

## Review Focus

- Allowed DNS becoming blocked on retry must never reuse the old permitted address; mixed answers may select one permitted candidate. Task 1: `pull206_rebinding_rechecks_and_pins`.
- Cancellation after a blocking save starts must neither free the producer nor let deletion/recreation acknowledge early. Task 2: `pull206_save_delete_recreate_is_fenced`.
- An old RTMP unpublish/media callback after deletion/recreation must not finish, publish, save or remove the replacement session. Task 2: `pull206_stale_rtmp_callbacks_cannot_touch_replacement`.
- A disconnected attach request after service commitment must leave exactly one owned worker and claim; repeating identical config must not restart even a failed worker. Task 3: `pull206_canceled_attach_keeps_owned_worker`.
- Validating a later environment declaration must not leave earlier side effects, and a later local admission failure must unwind already started work without skipping HLS shutdown. Task 3: `pull206_startup_validation_and_unwind`.
