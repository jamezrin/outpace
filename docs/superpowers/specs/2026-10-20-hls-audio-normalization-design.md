# Live HLS audio normalization (#200)

Date: 2026-10-20. Status: specification and implementation plan approved. Scope amendment approved by the user on 2026-10-21: MPEG Layer II/III and AC3 conversion; MPEG Layer I is explicitly unsupported. This amendment supersedes the original Layer I conversion/generator requirement.

## Purpose and boundary

Add optional audio normalization for live HLS streams whose selected audio is MPEG Layer II/III or AC3. Preserve the existing native ADTS AAC and video-only paths. FFmpeg copies video and encodes selected audio to stereo AAC-LC, 48 kHz, 128 kbit/s. This is an architectural lifecycle addition: existing HLS packaging does not provide a supervised subprocess boundary or explicit worker cancellation.

Both native and compatibility live HLS share one adapter and packager per session key. FFmpeg emits MPEG-TS bytes into the existing packager, never playlists or files. Existing segment ceilings, window retention, PCR/access-point segmentation, URLs, authorization and compatibility pins remain authoritative. Raw TS continues to use the original session broadcast; VOD HLS remains unchanged. No video encoding, Safari guarantee, ABR, UI, silence insertion, language selection, fMP4, arbitrary FFmpeg arguments or general media pipeline is included. Copied video can remain incompatible with a particular player.

The approved choice is a native fast path plus a scoped subprocess. Always using FFmpeg would consume processes and alter healthy AAC streams unnecessarily. Deferral would leave the non-AAC gap; embedded codec bindings would expand build and linking scope.

## Existing boundaries and intended responsibilities

`ace-media/src/audio.rs` already implements conservative single-packet PSI parsing and ADTS preference. Extend that parser with read-only layout/decision metadata rather than introduce a second permissive parser. The media library stays silent and has no subprocess knowledge. Metadata identifies transport/program IDs, PMT/PCR/video PIDs, video type, selected audio PID/codec and effective layout identity.

`ace-engine/src/hls_audio.rs` will own enabled-mode classification, admission and subprocess supervision. `hls.rs` continues to own segmentation and retained media, with explicit generation-aware readiness and separately owned worker control. `manager.rs` owns shared worker entries, cancellation and teardown. Configuration/runtime handle the two options and startup preflight. Existing HTTP readiness consumers use the richer state, including compatibility cancellation/expiry checks. This describes component contracts, not an implementation sequence.

Today `HlsPackager::start` captures its own Arc in a detached task; that ownership must be removed. Manager finalization currently creates packagers synchronously under locks. Only cheap state/handle installation remains there; executable launch, I/O, process waits and worker joins happen outside those locks.

## Configuration and startup

Expose exactly two new environment options and corresponding configuration fields:

- `OUTPACE_HLS_AUDIO_NORMALIZE`: boolean, default `false`; accept `true`/`false` and `1`/`0`, reject other values at configuration load.
- `OUTPACE_FFMPEG_PATH`: executable path or bare executable name, default `ffmpeg`; reject an empty value when enabled. Resolve a bare name through PATH once during preflight and retain the resolved executable path for all children. No shell expansion or command string parsing.

Keep a separate cloned normalization configuration under `Config`/manager so `HlsConfig` remains Copy. Existing HLS tuning options remain available; no new queue, timeout, retry, codec or concurrency knobs are exposed. Disabled mode performs no executable lookup, probing or child admission and preserves existing media-selection and HTTP behavior.

Enabled startup must complete preflight before binding listeners or accepting sessions. Against the chosen executable, inspect MPEG-TS demuxer/muxer availability, native AAC encoder, MPEG audio Layer II/III decoders, AC3 decoder and pipe protocol. Also run a short generated-in-memory synthetic AC3 TS conversion through the production pipe/mapping/output configuration; no lavfi, ffprobe or network is required in production. The small synthetic preflight vector contains no external media or identifiers. This detects an advertised but unusable conversion path; it does not guarantee every source can decode. Each probe has a five-second deadline, all preflight work shares a ten-second absolute deadline, and captured probe stdout is capped at 256 KiB per invocation. Overflow, timeout, nonzero exit, missing capability or malformed smoke output fails startup with a concise capability error.

Preflight children execute sequentially and obey the same cleanup contract as streaming children. On error the startup path awaits cleanup before returning. No process is launched when disabled. Deployment supplies and maintains FFmpeg; the base Docker image and compose configuration do not install it automatically. Enabled containers require an operator-built image containing a preflight-compatible binary (and configured path if needed). README must document this prerequisite, the default-off behavior and quality/resource tradeoffs. No network or exposed bind default changes.

## Enabled input contract and selection

Accept unencrypted 188-byte TS, one current program, single-section PAT/PMT contained in single packets under the existing strict parser constraints. Require exactly one supported video elementary stream, limited to MPEG-2 video, H.264 or HEVC as understood by existing access-point detection, and a valid declared PCR PID. Audio-only, multiple video streams, scrambled streams, ambiguous/multiprogram or fragmented PSI are unsupported. Video-only means no audio and no unidentified private elementary streams, not an unrecognized audio layout treated as silence.

Prefer the first ADTS AAC entry in PMT order. Otherwise select the first MPEG audio or recognized AC3 entry in PMT order. PMT stream types 0x03/0x04 identify the MPEG audio family, not its layer. Only Layers II/III are supported for conversion; selected Layer I fails closed. Before admitting a child, inspect actual selected elementary-stream frame headers, including split PES/TS headers, and require two valid consecutive headers at computed frame boundaries. Continue checking frame boundaries during conversion so an unchanged PMT cannot conceal a later Layer I transition. Use constant-size parser state, no sync search or unbounded scan, and the existing classification byte budget/deadline. Incomplete evidence cannot authorize conversion; malformed/reserved/free-format headers fail closed. A new effective selected layout resets this evidence. This deliberately strict framing contract may reject malformed or unaligned MPEG inputs. AC3 recognition uses the existing validated private-stream descriptor rules. LATM, EAC3 and DTS cannot be selected. Unknown/private entries cannot establish a video-only layout. When a supported audio track exists, confidently identified competing audio may be excluded by existing selection rules; unidentified private entries make the enabled layout unsupported. Subtitle/data streams are not mapped into transformed output. Native-path filtering keeps existing selector behavior for supported layouts.

No supported audio with any audio present is terminal unsupported input. Malformed, noncurrent or wrong-program tables do not replace a known valid layout; before classification they cannot establish readiness. A current unsupported selected-program layout fails closed, including after startup. ADTS and supported video-only layouts use native packaging with no child. Strict enabled classification may reject a layout that disabled mode historically passes through; this is deliberate and must be documented.

Classification starts on worker creation or generation invalidation and is bounded by the existing HLS startup timeout and a 1 MiB aggregate input budget. Accumulate packet-aligned bytes while waiting for fresh matching PSI and a video access point. On the first usable opening point, discard preceding payload, prepend fresh matching tables and replay only that generation's opening bytes. Hitting the budget before that point fails instead of sliding an unbounded history. The same startup deadline covers classification, process startup and completion of the configured number of new-generation startup segments; stages never restart the clock.

## Transformation and output contract

One child handles one transformed generation. Invoke the executable directly with fixed argument construction, stdin/stdout pipes, explicit MPEG-TS input/output, explicit selected video/audio PID maps, video copy and native AAC-LC output as specified above. Disable stdin command interaction, omit subtitles/data, restrict protocols to pipe, and never pass an input URL or media-derived command arguments other than validated numeric mapping/identity fields. Bound demux probing to 1 MiB and one second of media analysis; inability to establish the mapped streams fails closed rather than extending probing indefinitely. Codec/mux buffering inside FFmpeg remains outside Rust byte accounting.

Use one output program, preserving the source program/service ID and transport-stream ID. Assign deterministic output PIDs: PMT 4096, video 256, audio 257; output PCR must be on video 256. Configure repeated PAT/PMT at access points. These are local mux identifiers, not content identifiers. Validate actual output tables rather than assume flags enforce the contract. Reject extra programs/elementary streams, unexpected codecs/PIDs/PCR mapping, malformed output or inability to obtain fresh PSI/access points within the generation deadline. Native output retains native identities.

The packager derives its clock and table prefix exclusively from output PSI/PCR for transformed generations. It must never reuse source PCR PID or source PMT caches after remux. Reapply session service metadata using existing synthesized SDT behavior against the output service identity; suppress competing upstream/FFmpeg SDT as existing titled packaging does. Do not copy arbitrary source descriptors onto newly encoded audio. Preserve source-relative A/V timing through remux, allow timestamp rebasing only at generation boundaries, and do not request asynchronous audio stretching or frame duplication. The output validator and synthetic tests establish the supported FFmpeg contract, including effective timestamp offsets; byte-identical TS is neither expected nor required.

## State, HTTP readiness and recovery

Public state distinguishes `Starting`, `Ready`, `Recovering`, `Failed(reason)` and `Stopped`. Internal classification/native/transforming phases belong to the supervisor. Only completed segments from the current generation count toward `startup_segments`; retained old segments cannot satisfy readiness. Publish state changes and notify all waiters without lost-wakeup races. Snapshot readiness and playlist rendering atomically so a concurrent recovery cannot advertise an old ready playlist.

Playlist waits during Starting/Recovering are bounded by the request timeout and the generation deadline. Failed/Stopped wake waits immediately. Existing live HLS routes return HTTP 503 with `Retry-After: 1` for unavailable media; existing invalid/expired authorization and removed-entry 404 semantics take precedence. Do not expose stderr or media-derived diagnostics in HTTP errors. Completed retained segments remain retrievable by sequence under existing authorization until normal eviction or entry teardown, even during recovery/failure; missing segments retain existing response semantics. A failed entry remains failed until session stop/idle teardown and a subsequent fresh start. A playlist retry never creates a crash retry loop.

A source discontinuity, broadcast lag, effective layout change or independent in-band transport discontinuity invalidates the current generation before further payload is accepted. Compare semantic program/PMT/PCR/video/audio selection and relevant descriptor changes; version-only repeats are not changes. Invalidate readiness, stop old pumps/child, discard old queued/input/partial segment/table/clock state, and classify again using fresh PSI and a fresh video access point. A layout-change packet may seed the new classifier only after old-generation output is fenced; cached earlier tables cannot stand in for fresh matching tables.

Keep completed segments and monotonically increasing media/discontinuity sequences. Mark exactly the first completed new-generation segment discontinuous; subsequent segments do not repeat it. Coalesce the out-of-band source recovery event and its paired in-band opening marker into one invalidation. Scope the dedup token to that recovery and consume/expire it at the first accepted opening access point, including when the marker appears on a filtered PID. Broadcast lag has no paired-marker contract. Output mux continuity resets during the opening of a replacement child belong to its already-announced boundary, not another restart. Old stdout carries a generation token and cannot enter a newer generation.

Permit three recovery invalidations per rolling 60 seconds per packager; initial start is not counted, coalesced markers count once, the fourth invalidation fails terminally. This bounds churn from unstable source/layout/lag events. Unexpected child exit (including exit zero while live), broken pipe, pump error/panic, unsupported layout, classification overflow/deadline, process-cap rejection or output stall fails terminally with no automatic crash restart or native fallback. Raw TS subscribers continue independently.

## Resource and ownership invariants

The numeric values below are fixed implementation constants selected for bounded behavior, not measured performance guarantees:

- One 1 MiB input byte budget per worker includes classification/replay buffers, queued bytes and the active stdin write slice. Use byte permits, split large broadcast messages and release consumed slices; never retain a large source chunk behind a tiny slice without charging its allocation. The inherited bounded session broadcast is separate. A full queue backpressures only this HLS receiver; ensuing broadcast lag follows recovery policy. It cannot block session/raw producers.
- One supervisor plus at most three owned pumps (stdin, stdout, stderr) per worker, independent of chunk count. Fixed stdout reads of at most 32 KiB feed the bounded packager directly; no extra stdout queue. TS framing stages at most one incomplete packet. No task per write, line or segment.
- Continuously drain stderr with fixed reads and retain only an 8 KiB tail, without allocating unbounded lines. Treat it as private diagnostic data; operational `alog!` messages contain reason categories, generation and exit status, never raw stderr, source titles or command/media text. Eight KiB is enough for bounded diagnosis without retaining an arbitrary log stream.
- Four normalization children globally per daemon, shared across managers if multiple managers exist. Nonblocking admission fails the HLS entry immediately when exhausted; native paths consume no slot and no unbounded waiter queue is created. Keep permits until child wait confirms reaping. Replacement cannot overlap its predecessor. Preflight is sequential before streaming starts. Four bounds concurrent encoders but is not an RSS/CPU guarantee or a benchmark-based capacity recommendation.
- After readiness, fail when there is no valid complete output TS packet for 45 seconds while nonempty input remains pending or accepted input has not produced output. Start this deadline on the first pending/accepted input after the last output; it continues during a blocked write and does not reset on more input. A fully drained idle source alone does not trigger it. Starting/recovering uses the earlier absolute startup deadline. This matches the default startup patience and catches blocked pipes without a tight false-positive loop; it does not prove segment progress or detect every semantic source stall.

A manager entry owns public media state and a worker-control handle (cancellation plus join ownership). Workers may own a separate shared media-state allocation but never their entry/control owner or manager Arc. Stale HTTP Arcs can read retained state but cannot keep a worker alive. Stop/reap atomically detach entries and signal cancellation under lifecycle locks, then await cleanup outside all manager/media locks. Per-key start generation checks prevent a delayed initializer from reinstalling a stopped entry. No lock is held across subprocess launch, I/O or join awaits.

Supervisor owns Child and all pump handles. Every potentially blocked read/write/channel wait selects cancellation. Cleanup fences publication first, cancels writer, closes stdin, allows up to one second for graceful child exit, then requests kill and always waits. Cancel/join pumps, or abort and join a pump that cannot finish after handles close; do not detach them. One second bounds graceful drain latency; killed-process wait is mandatory and cannot honestly have a universal OS completion bound. No new generation/admission permit release occurs until reap. Cleanup itself is not abandoned when an HTTP request or outer initialization future is cancelled: transfer its ownership to a manager runtime cleanup tracker before returning.

Explicit daemon shutdown cancels the reaper and all entries, drains the cleanup tracker and awaits workers before runtime teardown. Manager Drop synchronously signals cancellation and leaves already-registered cleanup tasks runtime-owned; callers must use awaited shutdown before destroying the runtime. `kill_on_drop` is only a final safety net for abrupt runtime/process termination, not a claim that Drop can asynchronously reap. Startup failure uses the same awaited cleanup. Process-group management is unnecessary because the executable contract is a direct FFmpeg binary that launches no descendants; wrapper scripts are unsupported.

## Acceptance and future verification

All future test implementation is assigned to Luna; product implementation and review are assigned to Sol. The audit's suggestion of Luna product implementation is superseded. This specification adds no code, build, test execution, live validation, registry access or network changes.

Acceptance requires the following measurable evidence, using synthetic media only:

- Policy tests cover ADTS preference over earlier AC3/MPEG audio, ordered fallback, Layer II/III acceptance and Layer I rejection from actual headers, split/incomplete/invalid MPEG evidence, descriptor AC3, video-only, rejected codecs/private/PSI/encryption/video layouts, invalid versus unsupported tables and semantic versus version-only changes. Disabled regression tests preserve existing selected bytes, readiness/HTTP behavior and zero process launches, even with an invalid FFmpeg path.
- Runtime-generated short video plus sine inputs exercise AC3 and MPEG Layers II/III. Synthetic header fixtures prove Layer I rejection; no Layer I encoder or conversion acceptance is required. Each transformed output has one copied video and one AAC-LC stereo 48 kHz track, correct output program/PCR mapping, advancing timestamps and decodable nonzero audio. Compare demuxed video elementary payloads (excluding mux framing), allow at most one AAC frame of duration error plus source framing tolerance, and require A/V end drift at most 100 ms for a ten-second fixture. AAC plus AC3 and video-only cases prove zero child starts. Capability-dependent synthetic generation tools must be verified explicitly; unsupported test encoders cannot silently skip a claimed layer.
- Through the manager and both live HLS routes, synthetic media produces the configured count of new-generation segments, advancing playlists and identical retained segment bytes across route families. Raw broadcast bytes and VOD behavior match flag-off controls. Recovery/audio changes retain old segments, block playlists until new readiness, start on fresh tables/access points, produce exactly one boundary and reject stale-generation stdout. Version-only PMT repeats do not restart.
- Controlled fake children exercise early exit, stdin refusal, blocked writes, missing/partial stdout, stderr flood and pump failure. Assert the byte budgets and maximum task/child counts, immediate terminal waiter wakeup (within one second under the test scheduler), timeout boundaries with controlled time, no silent fallback, and no live child/unjoined pump after awaited stop/reap/shutdown/cancelled initialization. Three recoveries succeed; the fourth inside 60 seconds fails, and one outside the rolling window is admitted. A fifth simultaneous transform fails admission and a slot is reusable only after reap.
- Preflight tests cover missing executable/capabilities, capture overflow, deadlines, failed smoke output and cleanup; disabled startup never invokes a probe. HTTP authorization/expiry retains precedence over normalization state. Test helpers may use ffprobe; production does not depend on it.

The FFmpeg suite is optional locally with an explicit opt-in/skip notice. A designated CI job must install and verify FFmpeg plus required synthetic generators/ffprobe, enable that suite and fail when a prerequisite is missing. Ordinary offline policy/pump tests must not require FFmpeg. Later implementation validation includes workspace tests, clippy, formatting and identifier hygiene. No live-source or browser result is required for this scoped acceptance, and none establishes a Safari guarantee.

## Review decision

No unresolved configuration or lifecycle alternatives are delegated to implementation. Review should accept or revise the deliberate restrictions: one supported video/program, strict enabled PSI, stereo quality loss, fixed resource limits, terminal subprocess failures and operator-supplied FFmpeg. Written-spec approval is required before preparing an implementation plan; approval of that plan and its execution method remains a separate gate.
